# VideoKiwi

VideoKiwi는 텍스트와 이미지를 MiniMax H3 영상으로 만드는 로컬 웹 스튜디오입니다.  
브라우저에서 장면을 입력하면 프롬프트와 실행 조건을 준비하고, 이미 설치된 ComfyUI H3 엔진에 전달합니다.  
영상은 로컬 H3에서 만들며, 프롬프트 제안은 Claude Agent SDK와 서버 사용자의 Claude 구독 로그인을 사용합니다.  
제안 요청 시에는 설명과 선택한 이미지가 Claude에 전달됩니다. 외부 영상 생성 서비스는 사용하지 않습니다.

화면은 Windows와 Mac의 브라우저에서 사용할 수 있도록 만들었습니다.  
현재 엔진 연결은 `~/AI/H3-Local`에 준비된 Windows ComfyUI와 Q4 워크플로를 기준으로 구현했습니다.  
웹 화면이 Mac에서 열린다는 사실과 H3 모델이 Mac GPU에서 실행된다는 사실은 별개입니다.

## 실행하기

Node.js 22.12 이상과 실행 중인 ComfyUI H3가 필요합니다. 프로젝트 폴더에서 다음 명령을 실행합니다.

```bash
npm ci
npm run dev
```

브라우저에서 [VideoKiwi](http://127.0.0.1:3010)를 엽니다. 기본 엔진 주소는 `http://127.0.0.1:8188`입니다.  
이 PC에서는 기존 `~/AI/H3-Local/start-h3.cmd`로 엔진을 실행할 수 있습니다. 이미 켜져 있으면 그대로 사용합니다.

주소와 저장 폴더를 바꾸려면 `.env.example`을 `.env`로 복사해 수정합니다.  
업로드 이미지와 생성 기록은 기본적으로 프로젝트의 `.data` 폴더에 저장되며 Git에 포함되지 않습니다.  
생성된 원본 MP4는 기존 ComfyUI 출력 폴더에 남습니다. 웹 화면에서 브라우저로 내려받을 수 있습니다.

배포용 파일을 빌드해 같은 컴퓨터에서 실행할 수도 있습니다.

```bash
npm run build
npm start
```

## Mac에서 Windows GPU 사용하기

Windows에서 이 앱과 H3 엔진을 실행하면 Mac에서는 브라우저만 사용할 수 있습니다.  
이미 SSH 연결 환경이 있다면 Mac 터미널에서 웹 포트만 전달하는 방법이 간단합니다.

```bash
ssh -L 3010:127.0.0.1:3010 사용자명@Windows주소
```

이후 Mac에서 `http://127.0.0.1:3010`을 엽니다. H3 엔진의 8188 포트를 네트워크에 공개할 필요는 없습니다.

같은 신뢰할 수 있는 네트워크에서 직접 접속하려면 Windows의 `.env`에 다음 값을 지정합니다.

```dotenv
HOST=0.0.0.0
PORT=3010
VIDEOKIWI_ACCESS_TOKEN=16자_이상의_접속_비밀번호
```

서버를 다시 실행한 뒤 Mac에서 `http://Windows의_IP:3010`으로 접속합니다.  
브라우저 로그인 창의 사용자 이름에는 `videokiwi`, 비밀번호에는 위 값을 입력합니다.  
외부에 공개하는 서비스가 필요하다면 HTTPS와 사용자별 인증을 갖춘 배포 구성이 추가로 필요합니다.

## 영상을 만드는 흐름

1. 이미지 영상 또는 텍스트 영상을 선택합니다. 이미지 영상에는 시작 이미지가 필요합니다.
2. 피사체가 어떻게 움직이고 어떤 장면이 이어지는지 설명합니다. 필요하면 끝 이미지와 소리 설명을 추가합니다.
3. Claude에 프롬프트 제안을 요청하고 결과를 검토합니다. 제안문은 직접 고칠 수 있습니다.
4. 길이, 화면 비율, 실행 프로파일과 시드를 선택하고 영상을 만듭니다.
5. 기록에서 실행 상태와 사용한 설정을 확인하고, 완료된 영상과 실행 레시피를 내려받습니다.

**제목**은 기록을 구분하는 이름이며 선택 사항입니다. 영상 생성이나 Claude 제안에는 전달되지 않습니다.  
비워 두면 설명 원문을 제목 대신 보여 주고, 생성 뒤에도 상세 화면의 연필 버튼으로 고치거나 지울 수 있습니다.  
라이브러리 검색과 내려받는 파일 이름(예: `반계리 은행나무-a9e5647e.mp4`)에도 제목을 사용합니다.  
**이미지 설명**은 Claude가 시작 이미지를 이해하도록 돕는 문장이며, Claude 제안을 쓸 때만 참고합니다.

이미지는 PNG, JPG, WebP 정지 이미지를 지원합니다. 업로드는 10MB까지이며, 2048px 안으로 크기를 정리합니다.  
엔진이 다른 영상을 생성 중이면 새 작업을 제출하지 않습니다. 기존 작업이 끝난 뒤 다시 실행합니다.  
앱을 닫아도 엔진에 이미 제출된 작업을 자동으로 취소하지 않습니다.

## 영상 이어 만들기

이미 만든 영상의 끝에서 다음 장면을 이어서 생성합니다. Higgsfield의 Extend Video(Sequel) 흐름을 참고했습니다.

1. 왼쪽 위에서 **영상 이어 만들기**를 고릅니다. 기록 화면의 **이어서 생성** 버튼을 눌러도 됩니다.
2. 완료된 영상을 고르거나 내 컴퓨터의 MP4, MOV, WebM 영상(250MB, 5분 이하)을 불러옵니다.
3. 다음 장면에서 일어날 일을 적고, 추가 길이(5, 10, 15초)를 고른 뒤 **이어서 만들기**를 누릅니다.

원본의 마지막 22프레임(약 0.9초)과 그 구간의 소리를 H3 가이드로 넣어 움직임과 소리가 이어지게 합니다.  
생성이 끝나면 겹치는 22프레임을 잘라 내고 원본 뒤에 붙여 하나의 MP4로 저장합니다.  
붙이는 동안에는 `원본과 이어 붙이기` 단계로 표시되며, 실패하면 **상태 다시 확인**으로 붙이기만 다시 시도합니다.  
화면 크기는 원본 크기를 유지하고, 이어 만든 결과를 다시 골라 계속 늘릴 수 있습니다.  
원본 앞쪽에 장면을 만드는 Prequel 방향은 아직 지원하지 않습니다.

## 성능과 품질을 비교하는 방법

프롬프트 제안은 Claude가 입력 설명과 시작 이미지, 끝 이미지를 함께 참고해 작성합니다.  
기본 모델은 Claude Opus 5.5(`claude-opus-5-5`)이며, 실제 응답 모델도 검토 영역에 함께 보여 줍니다.  
장면, 환경음과 대사, 배경 음악을 H3의 세 구역으로 정리하고, 대사를 요청하지 않았다면 내레이션을 금지합니다.  
이미지의 가로와 세로, 밝기와 대표 색상은 별도로 로컬에서 측정해 실행 설정에 사용합니다.

제안 버튼은 영상을 생성하지 않습니다. 제안문은 원문 아래의 검토 영역에 나타납니다.  
그 상태에서 **영상 만들기**를 누르면 검토 영역의 문장을 사용하므로 원문 창에 복사할 필요가 없습니다.  
직접 수정한 문장도 다음 생성에 적용됩니다. 제안 영역을 닫으면 원문을 사용하는 흐름으로 돌아갑니다.  
자동 제안 옵션을 켜면 생성 전에 Claude를 호출합니다. 새 초안에서는 이 옵션이 기본으로 꺼져 있습니다.

서버를 실행하는 사용자가 Claude Code에 먼저 로그인해야 합니다. 이 앱은 로그인 토큰을 복사하거나 보관하지 않습니다.  
별도 API 키로 전환하지 않으며, 제안에 실패하면 오류를 보여 줍니다. 로컬 규칙의 결과를 Claude의 제안처럼 표시하지 않습니다.  
구독 사용 범위는 [Anthropic 공식 안내](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)를 따릅니다.

| 프로파일 | 실제 설정 | 비교할 때 볼 부분 |
|---|---|---|
| 빠르게 | Turbo LoRA와 Sigma Shift가 준비되면 Euler 8단계 | 짧은 시도로 구도와 동작을 확인합니다. |
| 균형 | 기본 모델과 `res_multistep` 20단계 | 기존 로컬 워크플로와 비교할 기준으로 사용합니다. |
| 품질 탐색 | 기본 모델과 `res_multistep` 30단계 | 같은 시드로 결과를 비교합니다. 단계 증가가 품질을 보장하지는 않습니다. |

Turbo LoRA가 준비되지 않았을 때는 기본 모델을 8단계로 줄이지 않고 20단계로 실행합니다.  
기본 크기는 가로 영상 기준 640×352이며, 표준 크기는 864×480입니다. 다른 비율도 픽셀 수를 고려해 계산합니다.  
H3의 프레임 규칙에 따라 5초 요청은 124프레임, 10초는 243프레임, 15초는 362프레임으로 맞춥니다.  
따라서 실제 길이는 24fps에서 약 5.167초, 10.125초, 15.083초입니다.

시드와 크기를 고정하고 프롬프트나 프로파일 중 한 가지만 바꾸면 비교가 쉬워집니다.  
실행 기록에는 원문, 제출한 개선문, 시드, 샘플러, 단계, 영상 크기와 경과 시간이 남습니다.  
경과 시간에는 대기와 모델 읽기 시간이 포함될 수 있으며 순수한 GPU 연산 시간과는 다릅니다.  
입력 점검표는 결과 영상의 품질 점수가 아닙니다.

영상 생성 중에는 ComfyUI의 WebSocket 이벤트로 현재 단계를 표시합니다.  
샘플링은 `3/8단계, 38%`처럼 실제 처리 횟수를 보여 주고, 영상 복원은 엔진이 제공하는 타일 진행 수치를 보여 줍니다.  
이 수치는 현재 단계의 진행률입니다. 샘플링이 100%여도 복원과 저장이 남을 수 있어 전체 완료와 구분합니다.  
수치가 없는 모델 준비나 입력 인코딩 구간에는 단계명과 경과 시간을 표시하며, 남은 시간을 임의로 계산하지 않습니다.

## 확인한 범위

Higgsfield의 H3 작업 화면은 REA MCP로 직접 열어 이미지 입력, 프롬프트, 설정과 기록 영역을 관찰했습니다.  
실제 생성 엔진은 그 서비스의 API를 사용하지 않고 기존 로컬 H3 소스와 연결했습니다.  
관찰 근거와 설계 선택은 [분석 기록](docs/reverse-engineering.md)에, 실행 규칙은 [하네스 문서](docs/harness.md)에 있습니다.

처음에는 GPU 생성 시험을 보류했으며, 사용자가 GPU 사용을 허용한 뒤 실제 시험을 진행했습니다.  
이 웹 앱에서 이미지 입력과 텍스트 입력을 각각 H3에 제출해 영상과 음성 생성, 다운로드와 재생을 확인했습니다.  
640×352, 124프레임, Turbo 8단계 기준 이미지 입력은 약 165초, 텍스트 입력은 약 138초가 걸렸습니다.  
원문보다 개선 프롬프트의 품질이 좋은지는 별도의 비교 시험이 필요합니다.  
자세한 실행 근거와 미검증 범위는 [검증 기록](docs/verification.md)에 있습니다.

```bash
npm run typecheck
npm test
npm run build
npm run test:e2e
```

브라우저 통합 검사는 Chrome 또는 `BROWSER_EXECUTABLE`로 지정한 Chromium 브라우저와 FFmpeg를 사용합니다.  
이 검사에서 생성하는 단색 MP4는 통신과 재생을 확인하기 위한 테스트 파일입니다.

다음 명령은 실제 GPU를 사용합니다. 기본 이미지 시험은 `~/AI/H3-Local/generation-frame-000.png`를 사용하며,  
다른 이미지는 `VIDEOKIWI_TEST_IMAGE` 환경변수로 지정할 수 있습니다. 엔진에 기존 작업이 있으면 제출하지 않습니다.

```bash
npm run test:gpu
npm run test:gpu -- --text
npm run test:gpu -- --progress
```

GPU 검사는 기본적으로 입력 문장을 그대로 사용합니다. `--progress`는 실제 샘플링 수신 여부도 검사합니다.  
Claude 제안까지 함께 검사하려면 `--suggest`를 추가합니다. 이 경우 Claude 구독 요청이 발생합니다.

## 코드 위치

| 위치 | 하는 일 |
|---|---|
| `src/renderer` | 브라우저 화면과 HTTP 클라이언트를 구현합니다. |
| `src/server/harness.ts` | 입력을 검사하고 프롬프트와 실행 계획을 준비합니다. |
| `src/server/comfy.ts` | 로컬 ComfyUI에 업로드, 제출, 조회와 지정 작업 취소를 요청합니다. |
| `src/server/service.ts` | 작업 수명, 중복 제출 방지, 재연결과 기록을 관리합니다. |
| `src/server/store.ts` | 작업 기록과 이미지 목록을 파일에 저장합니다. |
| `src/server/workflows` | 기존 Q4 기본 워크플로와 Turbo 워크플로의 사본을 보관합니다. |
| `test` | 입력과 연결 계약, 모의 엔진을 이용한 통합 흐름을 검사합니다. |

작업 제출의 응답이 유실되면 같은 작업을 자동으로 다시 보내지 않습니다.  
대신 기록에 확인 필요 상태를 남깁니다. 엔진 연결이 잠시 끊겼을 때는 작업 ID를 유지해 다시 확인합니다.  
자동 확인은 한 시간 뒤 멈추며, 엔진 작업은 유지합니다. 기록에서 새로고침하면 다시 상태를 확인할 수 있습니다.
