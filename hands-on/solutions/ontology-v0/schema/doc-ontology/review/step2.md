# 2단계 검토: 역량 질문과 건너가는 지점 `[단계 ①]`

- 승인하는 것: 기본 질문 4가지의 답, 역량 질문 23개와 그 범위, 범위 밖으로 둔 질문 3개,
  건너가는 지점 6곳
- 승인하면 다음에 일어나는 일: 이 목록을 「답할 범위」로 확정하고, 3단계(추출 단위와 표본 계획)로 넘어감.
  4단계에서 LLM에게 넘기는 예시 질문과 8단계 시험의 채점 기준이 이 목록에서 나옴
- 온톨로지 적용(요소: 답할 범위): 여러 원천을 거치는 질문을 함께 정하고, 원천이 바뀌는 자리(건너가는 지점)를 적음.
  기존 스키마 설계의 ① 단계는 문서 종류마다 질문만 정했음. 이번에는 4절과 5절이 더해짐

## 1. 기본 질문 4가지

### 개념 설명
역량 질문을 쓰기 전에 「무엇을, 어디에 쓰려고, 누가 쓰는가」를 먼저 정함(Ontology 101의 Step 1).
용도와 쓰는 사람이 달라지면 담을 정보가 달라지기 때문임. 아래는 AI가 쓴 초안이며 틀린 곳이 있으면 고쳐 주시면 됨.

| 기본 질문 | 답(초안) |
|---|---|
| 도메인 | 가상 카드사 한빛카드의 개인회원 이용약관, 카드 혜택 안내, 상담 기록. 이어지는 다른 원천은 정형 DB(회원, 카드, 상품, 가맹점, 거래) |
| 용도 | 상담을 돕는 에이전트의 그래프 검색(GraphRAG). 조항과 혜택과 상담 내용을 관계로 찾고, 여러 문서와 정형 DB를 이어 답함 |
| 답할 질문 유형 | 아래 question_types의 9가지 |
| 쓰는 사람과 관리하는 사람 | 쓰는 사람은 상담사와 감사자(회원을 지정해 조회하는 사람). 관리하는 사람은 스키마를 검토하고 승인하는 지식 담당자(이 실습에서는 강사) |

열 뜻
- 기본 질문: 역량 질문 가이드 2절이 먼저 답하라고 한 4가지
- 답(초안): 프로젝트 자료(평가 질문, 실습 README)를 보고 AI가 쓴 답

## 2. 질문 유형

### 개념 설명
질문 유형은 사용자 질문에서 사람 이름, 카드 이름, 날짜, 금액 같은 값을 빈칸으로 바꾼 뒤 틀이 같은 것끼리 묶은 것임.
질문 유형마다 역량 질문을 1개 이상 써야 사용자가 실제로 묻는 것이 빠지지 않음.
사용자 질문은 평가 질문 25개(Q01 ~ Q25)와 실습 README의 검색 예시 1개임.

| 유형 | 질문 틀 | 묶인 사용자 질문 |
|---|---|---|
| T1 | {약관 주제}의 조건, 기한, 처리 방법은? | Q01, Q02, Q03, Q04, Q05, Q06, Q18, Q20 |
| T2 | {카드}의 {혜택}은 얼마이고 한도, 조건, 사용 기한은? | Q07, Q08, Q09, Q10, Q11, Q12, Q13, Q19 |
| T3 | {회원}은 첫 상담에서 무엇을 요청했고 가장 최근 상담에서는 어디까지 진행했나? | Q14, Q16, Q21, Q22 |
| T4 | {회원}이 {제안}을 원하지 않은 까닭은? 피해야 할 설명이나 제안은? | Q15, Q17 |
| T5 | 고객군별로 고객이 말한 불만을 주제별로 나누면? | Q23 |
| T6 | 고객이 받아들인 제안의 공통점은? | Q24 |
| T7 | 불만 주제마다 관련된 약관 조항과 카드 혜택은? | Q25 |
| T8 | {회원}이 많이 쓰는 업종에 혜택을 주는 카드는? | README 예시 |
| T9 | 번호로 지정한 {회원}의 상담 기록은? | Q14, Q15, Q16, Q17, Q21, Q22 |

열 뜻
- 유형: 질문 유형의 번호
- 질문 틀: 값을 `{빈칸}`으로 바꾼 질문의 틀
- 묶인 사용자 질문: 이 틀에 해당하는 사용자 질문의 번호. Q18 ~ Q22는 문서에 답이 없는 질문임(답이 없어야 하는 시험에 씀)

## 3. 범위

### 개념 설명
범위는 그 질문에 답하려면 어디까지 봐야 하는지를 나눈 것임.
문서 하나 안에서 답하는 질문만 보고 설계하면, 여러 문서를 잇거나 다른 원천과 함께 봐야 하는 질문에 필요한 연결이 빠짐.
그래서 질문마다 범위를 적고, 뒤의 세 범위가 필요한지 사용자가 확인함.

| 범위 | 뜻 | 역량 질문 수 |
|---|---|---|
| 문서 하나 | 한 문서 종류의 단위 하나 안에서 답함 | 15 |
| 여러 문서 종류 | 둘 이상의 문서 종류를 이어야 답함 | 3 |
| 전체 모음 | 많은 단위를 모아 공통점, 주제, 집단별 차이를 답함 | 2 |
| 문서와 다른 원천 | 다른 원천의 값과 문서를 함께 봐야 답함 | 3 |

열 뜻
- 범위: 답하려면 봐야 하는 넓이
- 역량 질문 수: 그 범위로 적은 역량 질문의 수
- 단위: LLM에 한 번에 넣는 글 조각(3단계에서 정함). 원천: 데이터가 나온 곳(문서 3종과 정형 DB)

## 4. 역량 질문

### 개념 설명
역량 질문은 지식 그래프가 답할 수 있어야 하는 질문임. 그래프에 무엇을 담고 무엇을 뺄지를 이 질문으로 정함.
답이 될 노드 타입(그래프의 점 종류)이나 관계(점을 잇는 선) 이름은 일부러 쓰지 않았음.
이름을 미리 쓰면 LLM이 그 이름만 따라 써서 다른 후보가 나오지 않기 때문임.

| 번호 | 범위 | 관련 문서 종류 | 질문 유형 | 역량 질문 | 근거가 된 사용자 질문 |
|---|---|---|---|---|---|
| R1 | 문서 하나 | 약관 | {약관 주제}의 조건, 기한, 처리 방법은? | 이 조항은 어떤 경우에 무엇을 하도록 정하는가? | Q01, Q05, Q06 |
| R2 | 문서 하나 | 약관 | {약관 주제}의 조건, 기한, 처리 방법은? | 이 조항이 정한 기한이나 기준 금액은 얼마인가? | Q01, Q02, Q03, Q04 |
| R3 | 문서 하나 | 약관 | {약관 주제}의 조건, 기한, 처리 방법은? | 이 조항의 절차는 어떻게 진행되고 결과는 언제 알리는가? | Q03, Q04, Q06 |
| R4 | 문서 하나 | 약관 | {약관 주제}의 조건, 기한, 처리 방법은? | 이 조항은 다른 어느 조항을 따르라고 하는가? | AI 제안(약관 청크 15건 중 3건이 다른 조항을 가리킴) |
| B1 | 문서 하나 | 카드 혜택 안내 | {카드}의 {혜택}은 얼마이고 한도, 조건, 사용 기한은? | 이 카드에는 어떤 혜택이 있고 혜택마다 얼마(비율, 금액, 횟수)를 주는가? | Q07, Q09, Q10, Q11, Q12 |
| B2 | 문서 하나 | 카드 혜택 안내 | {카드}의 {혜택}은 얼마이고 한도, 조건, 사용 기한은? | 이 혜택을 받으려면 어떤 조건(전월 실적, 대상 가맹점이나 결제 방식, 등록)을 채워야 하는가? | Q08, Q09 |
| B3 | 문서 하나 | 카드 혜택 안내 | {카드}의 {혜택}은 얼마이고 한도, 조건, 사용 기한은? | 이 혜택의 한도와 사용 기한, 지급 시점은 언제 얼마인가? | Q07, Q09, Q10, Q11, Q12 |
| B4 | 문서 하나 | 카드 혜택 안내 | {카드}의 {혜택}은 얼마이고 한도, 조건, 사용 기한은? | 이 혜택에서 빠지는 거래는 무엇인가? | Q25(장보기 할인에서 앱 주문이 빠짐) |
| B5 | 문서 하나 | 카드 혜택 안내 | {카드}의 {혜택}은 얼마이고 한도, 조건, 사용 기한은? | 이 카드에 걸린 이용 제한(결제 한도 등)은 무엇인가? | Q13 |
| C1 | 문서 하나 | 상담 기록 | 고객군별로 고객이 말한 불만을 주제별로 나누면? | 이 상담에서 고객이 말한 불만이나 불편은 무엇인가? | Q23, Q25 |
| C2 | 문서 하나 | 상담 기록 | {회원}은 첫 상담에서 무엇을 요청했고 가장 최근 상담에서는 어디까지 진행했나? | 이 상담에서 고객이 요청한 것(비교 기준, 원하는 조건)은 무엇인가? | Q14, Q16, Q21 |
| C3 | 문서 하나 | 상담 기록 | {회원}이 {제안}을 원하지 않은 까닭은? 피해야 할 설명이나 제안은? | 상담사가 어떤 제안을 했고 고객은 받아들였는가? 거절했다면 까닭은 무엇인가? | Q15, Q17, Q24 |
| C4 | 문서 하나 | 상담 기록 | {회원}은 첫 상담에서 무엇을 요청했고 가장 최근 상담에서는 어디까지 진행했나? | 이 상담에서 일(해지, 전환, 신고 등)은 어디까지 진행되었는가? | Q14, Q16, Q22 |
| C5 | 문서 하나 | 상담 기록 | {회원}은 첫 상담에서 무엇을 요청했고 가장 최근 상담에서는 어디까지 진행했나? | 이 상담은 앞선 어느 상담과 이어지는가? | Q14, Q16(첫 상담과 최근 상담을 이어 물음. 상담 48건 중 36건이 앞선 상담 번호를 말함) |

| X2 | 문서와 다른 원천 | 상담 기록 | 번호로 지정한 {회원}의 상담 기록은? | 회원 번호로 지정한 회원의 상담 기록은 무엇이고, 첫 상담과 가장 최근 상담은 어느 것인가? | Q14, Q15, Q16, Q17, Q21, Q22(질문은 회원 번호로 묻고 문서에는 가명 ID만 있음) |
| X3 | 문서와 다른 원천 | 카드 혜택 안내 | {회원}이 많이 쓰는 업종에 혜택을 주는 카드는? | 회원이 가진 카드에는 어떤 혜택이 있는가? | AI 제안(정형 DB가 회원의 카드와 상품을 갖고 있고, 혜택 안내가 상품마다 있음) |

열 뜻
- 번호: R은 약관, B는 카드 혜택 안내, C는 상담 기록의 문서 하나 범위. A는 전체 모음, M은 여러 문서 종류, X는 문서와 다른 원천
- 관련 문서 종류: 답하려면 봐야 하는 문서 종류. 4단계에서는 그 문서 종류의 질문만 LLM에 예시로 넘김
- 질문 유형: 2절의 질문 틀
- 근거가 된 사용자 질문: 이 역량 질문이 나온 사용자 질문. 「AI 제안」은 사용자 질문에 없지만 문서를 보고 AI가 보탠 것임
- 고객군: 회원을 나눈 무리(신규 가입, 장기 보유, VIP, 휴면 직전, 다중 카드, 연회비 부담)

AI 제안 3개(R4, M3, X3)는 빼도 됨. 넣은 까닭은 「근거」 칸에 적었음.

### 범위 밖으로 둔 질문

| 범위 밖으로 둔 질문 | 까닭 |
|---|---|
| 이 카드의 연회비는 브랜드별로 얼마인가? | 정형 DB의 상품연회비(ProductAnnualFee)가 이미 가진 값임. 다른 원천이 가진 데이터는 그래프에 다시 싣지 않음. 사용자 질문에도 카드별 연회비 금액을 묻는 것이 없음 |
| 이전 판 약관에서는 기준이 얼마였나?(Q20) | 문서에 현재 판(1.2)만 있어 답이 없음. 답이 없어야 하는 질문으로 시험에만 씀 |
| 회원의 월별 사용액과 거래 건수는 얼마인가? | 상담 본문에 상담사가 읽어 준 숫자가 있지만 정형 DB의 거래가 원본임. 문서 그래프에 싣지 않음 |

열 뜻
- 범위 밖으로 둔 질문: 관련은 있지만 이번 그래프가 답하지 않기로 한 질문
- 까닭: 뺀 이유. 승인하면 이 내용은 그래프에 담지 않음

## 5. 건너가는 지점

### 개념 설명
건너가는 지점은 질문에 답하는 길에서 원천이 바뀌는 자리임. 예를 들어 「회원이 많이 쓰는 업종에 혜택을 주는 카드」는
정형 DB에서 업종을 알아낸 뒤 카드 혜택 안내로 넘어가야 답할 수 있음.
이 자리마다 두 원천이 **무엇으로** 이어지는지를 적어 둬야, 5단계에서 그 자리를 잇는 공통 개념과 규칙을 빠뜨리지 않음.
여기서는 개념 이름과 규칙을 정하지 않고 「어디서 무엇으로 이어져야 하는가」만 적음.

| 번호 | 질문 | 거치는 원천 | 이어지는 것 | 문서 쪽 단서 | 다른 원천의 키 후보 | 메모 |
|---|---|---|---|---|---|---|
| P1 | M1 | 상담 기록 → 약관 | 같은 주제(고객의 불만과 조항이 함께 말하는 주제) | 상담 본문의 불만 내용, 약관 조항의 제목과 본문 | 없음 | 키와 값 목록이 없음. 공통 개념 노드와 이름 맞추는 규칙을 5단계에서 정함 |
| P2 | M2 | 상담 기록 → 카드 혜택 안내 | 같은 주제(고객의 불만과 혜택이 함께 말하는 주제) | 상담 본문의 불만 내용, 혜택의 이름과 대상 | 없음 | 관련 혜택이 없는 주제도 있어야 함(없으면 없다고 답) |
| P3 | M3 | 상담 기록 → 카드 혜택 안내 | 같은 대상(카드 상품) | 상담 본문의 카드 이름(48건 모두 있음), 혜택 안내 메타데이터 card_id와 card_name(195건, 64종) | Product.product_id | 상담 쪽에는 카드 이름만 있고 ID가 없음. 이름으로 ID를 찾는 방법을 5단계에서 정함 |
| P4 | X1 | 정형 DB(회원의 업종별 사용액) → 카드 혜택 안내 | 같은 분류 값(업종) | 혜택의 대상을 적은 문장(예: 가상 편의점, 마트, 커피점의 직접 결제) | Merchant.category(값 목록: inputs/value_lists.json의 업종 8개) | 정형 DB는 정해진 값, 문서는 문장이라 표현이 다름. 값 맞추기 표가 필요해 보임 |
| P5 | X2 | 정형 DB(회원) → 상담 기록 | 같은 대상(회원) | 상담 기록 메타데이터 member_pseudo_id(48건, 12종) | Member.member_id | 값의 꼴이 다름. 문서에는 가명 ID만 있어 바꾸는 규칙이 필요함(RAG 인덱서의 member_pseudonym 함수가 만든 값) |
| P6 | X3 | 정형 DB(회원이 가진 카드와 상품) → 카드 혜택 안내 | 같은 대상(카드 상품) | 혜택 안내 메타데이터 card_id(195건, 64종) | Product.product_id(키 값 목록: inputs/key_values.json의 상품 ID 64개(D2-C001 ~ D2-C064)) | 두 값의 범위가 같음. 값이 같으면 같은 상품으로 볼 수 있어 보임 |

열 뜻
- 질문: 4절의 역량 질문 번호
- 거치는 원천: 답을 찾는 순서대로 적은 원천
- 이어지는 것: 같은 대상(두 원천이 같은 개체를 가리킴. 키 값으로 이음), 같은 분류 값(두 원천이 같은 분류의 값을 가짐.
  값 목록으로 이음), 같은 주제(두 문서가 같은 주제를 말함. 키도 값 목록도 없음) 가운데 하나와 괄호 안의 이어 주는 것
- 문서 쪽 단서: 문서에서 그 대상이나 값이 나타나는 곳. 괄호의 숫자는 1단계 사본에서 센 것임
- 다른 원천의 키 후보: 원천 목록 표(sources.json)에서 찾은 라벨과 속성. 키는 대상 하나를 가려내는 값임
- 메모: 5단계에서 풀어야 할 점

- A1(고객군마다 어떤 주제의 불만이 나왔는가): 범위는 전체 모음이지만 「고객군」은 정형 DB의 Member.segment_id(값 6개)와 같은 분류임. 문서 쪽에서는 원본 파일 이름(예: D3_S01_신규가입_상담이력_합성.txt)에만 있음. 5단계에서 분류 Class 후보로 봄  

읽는 법 예시(P4): 정형 DB에서 회원의 업종별 사용액을 구함 → 「업종」 값으로 카드 혜택 안내에 건너감.
정형 DB의 업종은 정해진 8개 값이고 혜택 안내는 문장이라, 둘을 맞추는 표가 있어야 건너갈 수 있음.
