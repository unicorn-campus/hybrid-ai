# 3단계 검토: 추출 단위, 묶음 기준, 표본 계획

- 승인하는 것: 문서 종류마다의 추출 단위와 나누는 규칙, 묶음 기준, 발견용과 시험용 표본 건수  
- 승인하면 다음에 일어나는 일: 4단계에서 발견용 표본을 1건씩 LLM(Groq)에 넣어 스키마 후보를 뽑음(최대 181회 호출).  
  4 ~ 8단계와 나중의 인덱싱이 모두 여기서 정한 단위를 씀  
- 온톨로지 적용: 없음(준비 단계). 다만 3절의 「메타데이터 노드 후보」가 5단계에서 공통 개념을 정할 때 쓰임  
- 숫자는 모두 `tools/plan_samples.py`를 2026-11-18에 실행해 센 값임(고정 시드 20261118)  

## 1. 추출 단위

### 개념 설명
추출 단위는 LLM에 한 번에 넣는 글의 크기임. 한 조각에 조항이나 항목이 여러 개 묶여 있으면 LLM이 목록만 뽑고  
조건이나 기한 같은 내용을 놓치기 쉬움. 그래서 한 청크에 제목이 여럿이면 제목 줄을 경계로 나눔.  
검색용 청크는 다시 만들지 않고, 추출 직전에만 같은 규칙으로 나눠 넣음.  

| 문서 종류 | 추출 단위 | 나누는 규칙 | 본 청크 수 | 청크당 제목 줄 수 | 나온 단위 수 | 단위가 없는 청크와 이유 |
|---|---|---|---|---|---|---|
| 약관(regulation) | 조항 하나 | 제목 꼴 `제N조(제목)` 줄에서 나눔. `제N장 …` 줄은 버림. 제목 줄이 없는 청크는 청크째로 한 단위 | 15(전부) | 0개 3건, 4 ~ 6개 10건, 21개와 31개 2건 | 55 | 2건(D1-0003, D1-0004). 제목만 이어진 차례라 본문이 없음 |
| 카드 혜택 안내(benefit_guide) | 혜택 항목 하나 | 제목 꼴 `D2-C000-B00 \| 혜택 이름` 줄에서 나눔. 첫 줄의 `[카드: …]` 머리줄과 첫 제목 앞의 연회비 표는 버림. 제목 줄이 없는 청크는 청크째로 한 단위 | 30 | 0개 3건, 1개 17건, 2개 10건 | 40 | 없음 |
| 상담 기록(consult_log) | 청크 그대로(상담 한 건) | 나누지 않음 | 30 | `[상담ID]` 줄이 청크마다 1개 | 30 | 없음 |

열 뜻  
- 추출 단위: LLM에 한 번에 넣는 글 조각의 크기  
- 나누는 규칙: 청크를 단위로 자르는 방법. 제목 꼴은 정규식(글자 모양 규칙)으로 찾음  
- 본 청크 수: 제안 근거로 본 표본 청크 수. 문서 종류마다 고정 시드로 최대 30건을 고름  
- 청크당 제목 줄 수: 표본 청크에 제목 꼴 줄이 몇 개씩 들었는지의 분포  
- 나온 단위 수: 표본 청크를 규칙대로 나눴을 때 나온 단위 수  
- 단위가 없는 청크와 이유: 나눴더니 단위가 하나도 안 나온 청크  

근거와 확인한 것  
- 약관: 본문 청크 10건에 조항이 4 ~ 6개씩 들어 있고, 조항이 두 청크에 걸친 곳은 없음(같은 조 번호가 두 번 나온 것 0건)  
- 카드 혜택 안내: 혜택 ID 270종이 모두 한 청크에만 나옴. 카드마다 첫 청크의 제목 앞에 연회비 표가 있음(64건)  
- 연회비 표를 버리는 까닭: 카드별 연회비 금액은 2단계에서 범위 밖으로 승인됨(정형 DB가 가진 값). 검색용 청크에는 그대로 남음  
- 머리줄: 나눈 단위에는 본문에 카드 이름이나 상담 ID가 없을 수 있어, LLM에 넣을 때 단위 앞에 한 줄을 붙임  

단위의 예(약관, 앞에 붙는 머리줄 포함)  

```text
[문서: 개인회원 이용약관 | 조항: 제36조 회원의 계약 해지]
제36조(회원의 계약 해지)
① 회원은 앱, 웹 또는 고객지원 채널에서 계약 해지를 신청할 수 있습니다.
② 미청구 거래, 할부 잔액, 자동납부와 포인트를 확인한 뒤 종료합니다. 연회비 반환은 제10조에 따릅니다.
```

단위의 예(카드 혜택 안내의 머리줄)  

```text
[문서: 카드 혜택 안내 | 카드 ID: D2-C018 | 카드 이름: 한빛 쇼핑나들이 | 혜택 ID: D2-C018-B01]
```

## 2. 묶음 기준

### 개념 설명
묶음은 문서 종류 안에서 성격이 비슷한 단위끼리 나눈 무리임. 표본을 묶음마다 따로 뽑으면 수가 적은 무리도 빠지지 않음.  
기준은 메타데이터 필드 가운데 값이 2 ~ 10개쯤인 것을 먼저 보고, 없으면 제목의 모양으로 나눔.  
나누는 의미가 있는지는 역량 질문에 비춰 판단함(질문마다 답이 나올 무리가 갈리는지).  

| 문서 종류 | 묶음 기준 | 묶음 이름 | 묶음별 단위 수 | 근거 |
|---|---|---|---|---|
| 약관 | 제목 줄이 있는지 | 조항, 조항 아님 | 52, 3 | 메타데이터가 page뿐이라 묶을 필드가 없음. 장(7개)으로 나누면 묶음마다 조항이 4 ~ 10개뿐이라 시험용과 발견용으로 가를 수 없음. 표지, 문서 정보, 각주는 답이 없어야 하는 단위라 따로 묶음 |
| 카드 혜택 안내 | 혜택 제목의 낱말 | 할인, 적립, 캐시백, 이용 기준, 그 밖, 항목 아님 | 86, 66, 22, 54, 42, 13 | card_id와 card_name은 64종이라 너무 많음. 혜택 종류에 따라 B1(얼마를 주는가)의 답 모양이 비율, 금액, 횟수로 갈리고, B5(이용 제한)의 답은 「이용 기준」 항목에만 있음 |
| 상담 기록 | 원본 파일 이름의 고객군 | 신규가입, 장기보유, VIP, 휴면직전, 다중카드, 연회비부담 | 8, 8, 8, 7, 8, 7 | A1(고객군마다 어떤 주제의 불만이 나왔는가)이 고객군으로 무리를 나눔. channel(3종)은 어느 역량 질문에도 쓰이지 않음 |

열 뜻  
- 묶음 기준: 단위를 무리로 나누는 잣대  
- 묶음별 단위 수: 그 묶음에 든 단위 수(묶음 이름 순서대로). 상담 기록의 7건은 생일이 남아 뺀 청크가 든 묶음임  
- 근거: 그 기준을 고른 까닭과 관련 역량 질문 번호(R, B, C, A, M, X는 2단계의 번호)  
- 「그 밖」: 제목에 할인, 적립, 캐시백, 기준, 한도가 없는 혜택(예: 포인트 재충전, 무이자 할부, 연간 보너스, 바우처)  
- 「항목 아님」: 혜택 제목 줄이 없는 청크(표지, 적용 기준, 카드 찾아보기 4건, 참고 자료 7건)  

## 3. 메타데이터 노드 후보(5단계로 넘김)

### 개념 설명
청크에 딸린 메타데이터나 제목 줄의 값 가운데, 역량 질문의 답이 되거나 무리를 나누는 기준이 되는 것이 있음.  
이런 값은 LLM이 본문에서 뽑게 하지 않고 머리줄 값으로 그대로 채움(틀릴 일이 없고 값이 흔들리지 않음).  
여기서는 후보만 적고, 노드(그래프의 점)로 둘지 속성(점에 딸린 값)으로 둘지는 5단계에서 정함.  

| 문서 종류 | 값이 나오는 곳 | 값 종류 수 | 쓰임 |
|---|---|---|---|
| 상담 기록 | source(파일 이름의 고객군) | 6 | A1이 고객군으로 무리를 나눔. 값 목록의 고객군 6개와 같은 분류 |
| 상담 기록 | member_pseudo_id | 12 | X2와 건너가는 지점 P5(회원). 같은 회원의 상담을 이음 |
| 상담 기록 | record_id | 48 | 상담 한 건을 가려내는 키. C5(앞선 상담과 이어짐) |
| 상담 기록 | consult_date | 34 | 첫 상담과 가장 최근 상담을 가리는 날짜. 묶는 값이 아니라 속성 후보 |
| 카드 혜택 안내 | card_id, card_name | 64 | 건너가는 지점 P3, P6(카드 상품). 정형 DB의 Product.product_id와 범위가 같음 |
| 카드 혜택 안내 | 혜택 제목 줄의 혜택 ID | 270 | 혜택 한 건을 가려내는 키 |
| 약관 | 조 제목 줄의 조 번호와 제목 | 52 | 조항 하나를 가려내는 키. R4(다른 조항을 가리킴)와 M1 |

열 뜻  
- 값이 나오는 곳: 메타데이터 필드 이름이나 제목 줄  
- 값 종류 수: 서로 다른 값의 수  
- 쓰임: 그 값을 쓰는 역량 질문이나 건너가는 지점(P는 2단계의 번호)  
- 키: 대상 하나를 가려내는 값  

## 4. 표본 계획

### 개념 설명
표본은 두 가지로 나눔. 발견용은 4단계에서 스키마 후보를 뽑는 데 쓰고, 시험용은 7 ~ 8단계에서 스키마 초안을 시험하는 데 씀.  
둘이 겹치면 이미 본 글로 시험하게 되어 결과가 실제보다 좋게 보이므로 겹치지 않게 뽑음.  
청크 순서를 고정 시드로 정하고, 청크를 하나씩 나눠 시험용을 먼저 채운 뒤 발견용을 채움.  

| 문서 종류 | 추출 단위 | 묶음 | 단위 수 | 발견용(시작, 상한) | 시험용 | 시드 |
|---|---|---|---|---|---|---|
| 약관 | 조항 하나 | 조항 | 52 | 10, 25 | 27 | 20261118 |
| | | 조항 아님 | 3 | 쓰지 않음 | 3 | |
| | | 합계 | 55 | 최대 25 | 30 | |
| 카드 혜택 안내 | 혜택 항목 하나 | 할인 | 86 | 10, 30 | 8 | 20261119 |
| | | 적립 | 66 | 10, 30 | 8 | |
| | | 캐시백 | 22 | 10, 14 | 8 | |
| | | 이용 기준 | 54 | 10, 30 | 8 | |
| | | 그 밖 | 42 | 10, 30 | 8 | |
| | | 항목 아님 | 13 | 쓰지 않음 | 5 | |
| | | 합계 | 283 | 최대 134 | 45 | |
| 상담 기록 | 청크 그대로 | 고객군 6개(묶음마다 7 ~ 8건) | 46 | 묶음마다 3 ~ 4(전부) | 묶음마다 4 | 20261120 |
| | | 합계 | 46 | 22 | 24 | |

열 뜻  
- 단위 수: 그 묶음에 든 단위의 전체 수  
- 발견용(시작, 상한): 스키마 후보를 뽑을 때 처음 볼 건수와, 새 이름이 계속 나와도 넘지 않는 최대 건수.  
  시작 수를 본 뒤 새 타입이 3건 연속 안 나오면 그 묶음을 멈춤  
- 시험용: 스키마 초안을 시험할 건수. 발견용과 겹치지 않음(겹침 0건을 스크립트로 확인함)  
- 시드: 무작위 순서를 정하는 고정 숫자. 같은 시드면 다시 돌려도 같은 표본이 나옴  

알려 드릴 점  
- 단위가 모자람: 약관은 조항이 52개, 상담 기록은 46건뿐이라 시험용 기본값(30 ~ 50건)과 발견용을 함께 채우기 어려움.  
  약관은 시험용 30건(조항 27, 조항 아님 3), 상담 기록은 시험용 24건으로 잡음  
- 캐시백 묶음은 22건뿐이라 발견용 상한이 14건임  
- 시험용 건수가 적으면 지표의 오차가 큼: 비율을 95% 신뢰로 보면 24건은 약 ±20%p, 30건은 약 ±18%p, 45건은 약 ±15%p임.  
  역량 질문마다 답이 있는 표본은 이보다 적으므로, 8단계 숫자는 「대략의 수준」으로 읽어야 함  
- 답이 없어야 하는 단위: 약관의 조항 아님 3건(표지, 문서 정보, 각주), 카드 혜택 안내의 항목 아님 5건(카드 찾아보기, 참고 자료),  
  상담 기록에서는 불만이 없는 상담(예: 다중카드 고객군의 일반 문의)이 시험용에 들어감  
- 나누기: 약관 15청크와 카드 혜택 안내 197청크를 모두 나눴음. 캐시백 묶음이 상한에 못 미쳐 끝까지 찾아야 했기 때문임.  
  표본으로 쓰는 단위만 `units.json`에 저장함(약관 55개, 카드 혜택 안내 179개)  
- 생일이 남은 상담 청크 2건(D3-0028, D3-0048)은 1단계 승인대로 표본에서 뺌
