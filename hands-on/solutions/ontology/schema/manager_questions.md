# 관리자 확인 질문 (Phase 2)

자료만으로는 업무 기준을 정할 수 없고, 어떻게 보느냐에 따라 답이 달라지는 항목을 모음.  
'추천 답변(초안)'은 담당자가 그대로 승인하거나 고쳐 쓰도록 미리 적어 둔 것임.  
'관리자 결정'은 실제 회신을 받기 전까지 비워 둠.

담당자 역할은 Step 2.1에서 확인하지 못해 모두 **미지정**임.  
이 문서를 누구에게 보낼지부터 정해야 함.

## MQ-01 회원 번호로 상담 기록을 찾는 규칙을 그대로 써도 되는가

| 칸 | 내용 |
|---|---|
| 확인 번호 | MQ-01 |
| 관련 문항 | Q32, Q33 (확정) |
| 관련 역량 질문 | CQ-18, CQ-19 |
| 근거 위치 | `hands-on/solutions/rag/indexing/README.md` 203줄. 상담 청크 48건의 메타데이터 `member_pseudo_id`. 업무 뷰의 세션 조건 `app.member_id` |
| 질문 | 상담 기록의 회원 표시를 회원 번호에서 계산해 쓰는 방식을 이 설계에서 그대로 써도 됩니까? 문서 저장소의 식이 바뀔 때 알려 줄 담당자는 누구입니까? |
| 자료로 확인되는 부분 | 상담 쪽 회원 표시는 `"m_" + sha256(회원번호).hexdigest()[:16]` 로 만들어짐. 상담 이력이 있는 회원 12명의 번호에 이 식을 적용해 상담 쪽 표시 12개와 하나씩 대조한 결과 12명 모두 맞았고, 식으로 설명되지 않는 표시는 없었음. 한쪽 방향만 되며 상담 표시에서 회원 번호는 계산할 수 없음 |
| 판단이 필요한 부분 | 이 식이 운영에서도 같은지. 식이 바뀌면 상담 검색이 통째로 어긋나므로 바뀔 때 알리는 길이 있는지. 상담 기록이 없는 회원 588명에게 빈 결과를 어떻게 안내할지 |
| 추천 답변(초안) | "식을 그대로 쓰되 이 설계가 그 식에 매여 있다는 것을 기록하고, 문서 저장소를 다시 만들 때 함께 점검한다." 근거: 안내 문서가 "식을 바꾸면 회원별 검색이 어긋난다"고 못 박고 있으며, 회원 12명 전부에서 맞는 것을 확인함 |
| 담당자 역할 | 사용자(담당자 역할을 맡음. 질문 파일의 담당자는 '미지정'이었음) |
| 상태 | 반영 완료 |
| 관리자 결정 | 추천 답변(초안)을 승인함. 결정한 사람: 사용자(담당자 역할을 맡음. 질문 파일의 담당자는 '미지정'이었음). 일시: 2026-11-29(대화에서 받음. 시각은 기록하지 않음). 회신 출처: 대화에서 받은 사용자 답 원문 "추천안대로 확정". 반영: 설계가 이미 그 식을 전제로 함(연결 지점 CP-03의 변환 규칙). 식에 매여 있다는 점은 `crossing_points.json`과 `approval.json`에 기록됨. 문서 저장소를 다시 만들 때 함께 점검하는 일은 운영 절차라 설계 변경 없음 |

## MQ-02 '직전 열두 달 이용금액'을 무엇으로 세는가

| 판단이 필요한 부분 | 취소 거래, 세금, 연회비, 상품권 구매를 빼는지. 열두 달 집계 뷰를 새로 열어 줄지 |
| 추천 답변(초안) | "면제 실적은 승인 거래만 더하고 취소 거래는 뺀다. 열두 달 집계는 업무 뷰를 새로 하나 열어 준다." 근거: 약관 제10조②가 승인 취소를 실적에서 뺀다고 적고 있으며, 지금 뷰로는 열두 달을 셀 수 없음 |
| 담당자 역할 | 사용자(담당자 역할을 맡음. 질문 파일의 담당자는 '미지정'이었음) |
| 상태 | 결정 기록 완료, 반영할 것 남음 |
| 관리자 결정 | 추천 답변(초안)을 승인함. 결정한 사람: 사용자(담당자 역할을 맡음. 질문 파일의 담당자는 '미지정'이었음). 일시: 2026-11-29(대화에서 받음. 시각은 기록하지 않음). 회신 출처: 대화에서 받은 사용자 답 원문 "추천안대로 확정". 반영: 남은 것: 열두 달 집계 업무 뷰가 RDB에 새로 열려야 CQ-01을 DB로 답할 수 있음(지금 `app.monthly_usage`는 여섯 달까지). 뷰가 생기면 RDB 매핑과 Turtle을 고쳐 새 버전으로 올려야 함. 승인 거래만 더하는 규칙은 약관 제10조②에서 읽는 문서 경로에 이미 있음 |
