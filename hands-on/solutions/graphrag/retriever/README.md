# GraphRAG 검색 실습 예제

하이브리드 AI 교육 「그래프 검색」(교재 『W05 ~ W07』 64 ~ 79쪽) 실습용 예제임.  
인덱싱 실습(`../indexer`)이 게시한 활성 세대(Neo4j 그래프 + OpenSearch 검색엔진)를 읽어,  
**Groq 에이전트(gpt-oss-120b)가 툴을 골라 근거를 모으고(ReAct), 판단은 의사결정AI Jev가 확률로, 막는 일은 코드가 맡는** 검색 워크플로우 10단계를 돌림.  
레이어드 아키텍처 없이 **main 1개 + 핵심 모듈 1개**로 짰고, 교육생은 핵심 모듈의 실습 함수 13개(직접 작성 10개, 빈칸 채우기 3개)를 채운 뒤 본인 코드로 바꿔 끼움.

## 수업용 명령 2개

가상환경은 상위 폴더 `hands-on/solutions/graphrag`에서 만들고 활성화함([상위 README 3절](../README.md#3-가상환경-설정과-패키지-설치)).  
활성화한 터미널에서 이 폴더(`retriever`)로 들어와 실행함.

```bash
python search_graph.py --qid Q01
```

```bash
python search_graph.py --qid Q19
```

첫 명령은 약관 사실 질문을 W1 ~ W10 끝까지 돌려 「답변 완료」를 봄(약 7 ~ 10초, 에이전트 비용 약 $0.001).  
둘째 명령은 함정 질문(가족돌봄 카드에 없는 해외 수수료 할인)이 지어내지 않고 「확인할 수 없음」으로 멈추는 것을 봄.  
프롬프트 앞에 `(.venv)`가 없으면 먼저 활성화함(3.2). 나머지 옵션은 8장에 있음.

## 1. 목표와 주요 기능

| 목표 | 내용 |
|---|---|
| 개념을 코드로 | 교재 70쪽 워크플로우(W1 요청 접수 → W2 질문 분석 → W3 검색 에이전트 ⇄ W4 툴 실행 → W5 채점과 상한 판정 → W6 리랭킹 → W7 수집 종료 판정 → W8 답변 생성 ⇄ W9 근거 검증 → W10 종료 상태)를 함수 하나씩으로 봄 |
| 클론 코딩 | 실습 함수 13개(직접 작성 10개, 빈칸 채우기 3개: `search_engine`, `local_search`, `global_search`). `my_search.py`에 채우고 `--mine` 옵션으로 바꿔 끼움 |
| 눈으로 확인 | Jev 확률과 코드의 결정, 회차마다 에이전트가 고른 툴과 질의, 진단 신호, 강제 종료 이유, 8자리, 코드 재확인, 인용 검증, 종료 상태, 에이전트 실제 비용을 화면에 찍음 |

주요 기능

- W3 ~ W5(반복 1)는 LangChain `create_agent` + 미들웨어 2개로 돎. `GuardMiddleware`(모델 호출 전 강제 종료, 모델이 고른 호출의 상한)와  
  `ToolWrapperMiddleware`(막힌 호출은 오류 표시, 실행한 결과에는 Jev 판정과 진단 신호)가 「막는 일은 코드」를 맡음  
- 툴 5개(`search_vector-bm25`, `local_search`, `global_search`, `get_source_chunks`, `finish`)는  
  입력에 필터 칸이 없음.  
  세대, 역할, 회원, 카드 필터는 래퍼가 강제로 붙임  
- 검색과 그래프는 청크 id만 돌려주고, 청크 글은 그 id로 검색엔진에서 그때그때 읽음(`read_chunk_texts`, Chunk 노드에는 글이 없음)  
- 글을 만드는 LLM 호출(G1, G2, W8)은 모두 LCEL 체인(`프롬프트 | 모델`)과 구조화 출력(`with_structured_output`, Pydantic 스키마)으로 짬
- 결과 끝에 W3 에이전트의 실제 비용(응답의 토큰 사용량 × Groq 단가)을 찍음. Groq가 앞부분이 같은 입력을 자동으로 캐시해  
  회차가 늘어도 입력 비용이 작음
- `--until W2`, `W5`, `W7`, `W10`으로 그 단계까지 수행하고, 그 단계까지의 결과를 한곳에 모아 보임(4.3)

## 3. 준비물과 가상환경 설정

| 항목 | 값 |
|---|---|
| Python | 3.13 |
| W3 검색 에이전트 | Groq `openai/gpt-oss-120b`(G1, G2, W8과 같은 모델), reasoning_effort medium. 단가는 100만 토큰당 입력 $0.15, 캐시된 입력 $0.075, 출력 $0.60(Groq 공식 모델 문서, 2026-10-25 확인) |
| W2, W5, W7 판단 | TypeSafe Jev(`jev-1.14.0` 고정). 확률만 내고 결정은 코드의 기준값이 함 |
| G1, G2, W8 | Groq `openai/gpt-oss-120b`(LCEL 체인 + 구조화 출력) |
| 임베딩, 리랭커 | Cohere `embed-v5.0-fast`(2048차원, 색인과 같음), `rerank-v4.0-fast` |
| 저장소 | Neo4j 2026.10.2 + APOC, OpenSearch 2.19.1(`backing-services/`) |
| API 키 | 저장소 루트 `secrets/.env`에 3줄: `JEV_API_KEY`, `GROQ_API_KEY`, `COHERE_API_KEY` |
| Neo4j 비밀번호 | 환경변수 `NEO4J_PASSWORD` 또는 `backing-services/neo4j/.env`(인덱싱과 같음) |

- 키는 환경변수에 올리지 않고 클라이언트마다 인자로 넘김. Jev는 SDK 기본 이름(`TYPESAFE_API_KEY`)과 달라 직접 넘김

### 3.1 사전 조건

1. 인덱싱 실습을 끝내 활성 세대가 있음(`../indexer/data/active_generation.json`). 없으면 인덱싱 README의 `--reuse data/teacher` 실행
2. Neo4j와 OpenSearch가 떠 있음(`docker compose -f neo4j/compose.yml ps`가 `healthy`)

### 3.2 가상환경(상위 폴더에서 만들고 활성화)

가상환경과 패키지 설치는 이 폴더가 아니라 **상위 폴더 `hands-on/solutions/graphrag`**에서 함(인덱싱 실습과 같은 `.venv`).  
만들기, 설치, PowerShell에서 활성화가 막힐 때 할 일은 [상위 README 3절](../README.md#3-가상환경-설정과-패키지-설치)을 따름.  
상위 `requirements.txt`에 검색용 패키지(typesafe-sdk, langgraph)까지 들어 있으므로 인덱싱 때 설치했으면 다시 설치하지 않아도 됨.

| 터미널 | 활성화하고 이 폴더로 들어오기 |
|---|---|
| Windows PowerShell | `cd hands-on\solutions\graphrag` → `.venv\Scripts\Activate.ps1` → `cd retriever` |
| Windows Git Bash | `cd hands-on/solutions/graphrag` → `source .venv/Scripts/activate` → `cd retriever` |
| macOS, Linux | `cd hands-on/solutions/graphrag` → `source .venv/bin/activate` → `cd retriever` |

PowerShell에서 「이 시스템에서 스크립트를 실행할 수 없으므로 ...」로 막히면 `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`를  
먼저 실행하고 다시 활성화함(지금 창에서만 허용. 상위 README 3.3).

설치 확인(활성화한 터미널에서)

```bash
python -c "import typesafe_sdk, langchain_groq, langchain_cohere, neo4j, opensearchpy; print('ok')"
```

## 4. 실행 방법

### 4.1 평가셋 질문(수업용)

```bash
python search_graph.py --qid Q14
```

역할과 회원은 평가셋 `filters`대로 정해짐(회원 질문은 감사자 + 그 회원, 경향 질문은 감사자, 나머지는 상담원).

### 4.2 자유 질문

```bash
python search_graph.py "할부로 산 상품의 철회는 며칠 안에 요청해야 하나요?" --role agent
```

```bash
python search_graph.py "이 회원이 가장 최근 상담에서 요청한 것은?" --role auditor --member-id M-1042
```

```bash
python search_graph.py "업종별로 혜택이 있는 카드명을 마크다운 표 형식으로 작성해요"
```

### 4.3 단계까지만 보기(--until)

그 단계까지만 수행하고, 그 단계까지의 결과를 `══ --until W5: … 까지 수행한 결과 ══` 머리줄 아래에 모아 보임.

```bash
python search_graph.py --qid Q01 --until W2   # W2까지: 지운 질문, 회원과 카드 필터, 핵심 낱말, Jev 확률, 코드의 결정, W3에 넘길 첫 메시지
python search_graph.py --qid Q01 --until W5   # W3 ~ W5 반복까지: 회차별 진단 신호, 남은 원문과 뺀 원문(Jev 확률), 엔티티, 보고서, 주제
python search_graph.py --qid Q01 --until W7   # W7까지: W6 최종 근거(리랭커 점수, 답 근거 확률), W7 코드 재확인, Jev, 판정
python search_graph.py --qid Q01 --until W10  # 끝까지(기본): 종료 상태, 답, 근거 목록(c1, c2 …)
```

- W2, W5, W7에서 멈추면 끝에 「끝까지 돌렸다면 갈 다음 단계」와 `── 멈춤(--until W5)` 줄이 찍힘. 로그 JSON의 `until`에 멈춘 단계가 남음
- 소문자(`--until w5`)도 받음
- 잡담이나 모호한 질문처럼 지정한 단계 전에 끝나면 그 자리의 W10 종료 상태를 보임

## 5. 단계별 출력 읽는 법

| 출력 머리 | 단계 | 봐야 할 것 |
|---|---|---|
| `── W1 요청 접수` | W1 | 준비 판정, 활성 세대, 보고서 수 |
| `── W2 질문 분석(코드)` | W2 | 회원번호를 지운 질문, 회원과 카드 필터, 볼 수 있는 청크 수, 핵심 낱말 |
| `W2 Jev` / `W2 코드의 결정` | W2 | 잡담, 모호 확률과 첫 툴(보기 순서를 바꾼 답 포함) → 코드가 내린 결정 |
| `── W3 회차 N/6` / `W3 →` | W3 | 에이전트가 고른 툴과 질의. 한 회차에 여러 개일 수 있음. 「막힘」은 상한에 걸린 호출 |
| `W4 툴 이름 … → 원문 N개` | W4 | 새 원문 수, 근거에서 뺀 수(관련 없음, 지시 끼워 넣기) |
| `W5 Jev` / `W5 신호` | W5 | 원문마다 관련, 답 근거, 질문 전제와 사실 충돌 확률. 진단 신호와 포함률, 공존 문장 수 |
| `W5 강제 종료` | W5 | 강제 종료 이유(모델을 다시 부르지 않음) |
| `── W6 리랭킹` | W6 | 8자리(Global 주제가 있으면 14자리)와 점수, 주제 id |
| `── W7 코드 재확인` / `W7 판정` | W7 | 조건 ①(한 문장 공존), ②(관계 하나로 이어짐) 결과와 통과, 불통과 |
| `── W8 답변` / `── W9 근거 검증` | W8 W9 | 문장마다 인용 id, 검증 실패 사유, 재작성 횟수 |
| `══ --until W10 ══` 아래 `[W10 종료 상태]`, `[답]`, `[근거]` | W10 | 종료 상태 이름과 뜻, 답, 근거 목록(답의 c1, c2 …와 같은 번호) |
| `[결과 파일]` | W10 | 최종 답변을 저장한 마크다운 파일 경로(`results/result_{YYMMDD}_{HHMMSS}.md`). 질문, 종료 상태, 답(표는 표 그대로), 근거, 경고 |
| `[비용과 호출 수]` | 전체 | 에이전트(Groq) 비용(호출, 입력, 캐시, 출력 토큰), 호출 수(원문 읽기 포함), 툴 경로, 시간 |

## 6. 교육생 교체 방법

1. `search_graph.py`는 고치지 않고 실행 명령에 `--mine`을 붙임. 처음 한 번 뼈대 `my_search.template.py`가 `my_search.py`로 복사됨  
   (`my_search.py`는 Git이 무시하므로 강사 저장소를 pull해도 충돌이 나지 않음. 자세한 내용은 `../README.md` 5장)

   ```bash
   python search_graph.py (기존 옵션)          # 강사 코드(core_search.py)로 실행
   python search_graph.py --mine (기존 옵션)   # 본인 코드(my_search.py)로 실행
   ```

2. `my_search.py` 맨 아래 `USE_TEACHER_CODE` 목록에서 **지금 채울 함수 이름을 지움**. 목록에 남은 함수는 강사 코드가 대신 돎
3. 그 함수를 채우고(직접 작성은 `NotImplementedError` 자리, 빈칸은 `"빈칸 N을 채울 것"` 자리) 같은 명령으로 다시 실행해  
   5장 출력을 강사 결과와 비교함. LLM은 실행마다 고르는 툴이 다를 수 있으므로 툴 경로보다 신호, 판정, 종료 상태를 비교함  
4. 막히면 이름을 목록에 다시 넣고 다음 함수로 넘어감(실습이 멈추지 않음)

실습 함수와 단계(채우는 순서)

| 순서 | 교시 | 함수 | 방식 | 단계와 하는 일 |
|---|---|---|---|---|
| 1 | 2 | `jev_route` | 직접 | W2 Jev에 잡담, 모호, 첫 툴을 묻고 확률만 받음(보기 순서를 뒤집어 한 번 더) |
| 2 | 2 | `build_agent` | 직접 | W3 create_agent로 ReAct 루프를 만들고 돌림 |
| 3 | 2 | `ToolWrapperMiddleware` | 직접 | W4 래퍼와 W5 채점: 막힌 호출은 오류 표시, 실행 결과에는 채점 글 |
| 4 | 2 | `run_tool` | 직접 | W4 입력 검사, 질의 속 식별자 지우기, 필터 강제 |
| 5 | 3 | `read_chunk_texts` | 직접 | W4 청크 id로 검색엔진에서 글 읽기(요청 안 캐시) |

### 7.6 L2 합치기 방식 비교(세대 gen-lab-lab-v4-cc97a472, 2026-11-23)

L2 엔티티 품질은 `eval-set-full.json`의 답이 있는 20문항을 local_search 한 번(원 질문)으로 돌려,  
결과 16개 중 정답 단서가 든 원문과 이어진 엔티티의 비율(정밀도)과 닿은 정답 원문 비율(재현율)을 셈.  
전체 흐름은 10문항 × 2회.

| L2 방식 | 정답 엔티티 포함 | 평균 정밀도 | 평균 재현율 | 근거 적중 | 함정 거절 | 답변 완료 |
|---|---|---|---|---|---|---|
| 검색엔진 갈래만(고정 없음) | 20/20 | 0.39 | 0.89 | - | - | - |
| 청크 엔티티 + 벡터 8개, 같은 코사인으로 합침(+ 고정) | 19/20 | 0.32 | 0.89 | 14/16 | 4/4 | 13/16 |

| 가중합 0.5 | 20/20 | 0.35 | 0.88 | 14/16 | 4/4 | 13/16 |

### 7.7 Global(경향 질문) 근거 보강(2026-11-24)

| 빠지는 곳 | 원인 |
