- 리드문: 식별자와 고유명사 질문을 기준으로 키워드 검색과 한국어 분석기의 효과를 확인합니다.

## 슬라이드 5. 하이브리드 검색과 리랭킹

- 제목: 검색 결합과 리랭킹의 효과를 따로 측정
- 리드문: 먼저 근거를 후보에 포함하고, 그다음 상위 근거의 순서를 정밀하게 조정합니다.
- 시각 배치: 상단 y 1.90 ~ 3.05″에 기존 검색 흐름, 하단에 좌우 w 7.2″ 설명을 둡니다.
  흐름은 BM25와 벡터를 병렬로 표시하고 융합 지점에서 합칩니다. 모든 연결은 편집 가능한 기본 개체로 유지합니다.
- 화면 본문 상단 흐름: 질문 → BM25 / 벡터 검색 → 후보 융합 → 리랭킹 → 상위 근거
- 화면 본문 좌측 「각 단계의 역할」:
  - 융합: 서로 다른 검색기의 후보 결합
  - RRF: 점수 대신 순위로 결합
  - 점수 융합: 정규화와 가중치 설정
  - 리랭커: 이미 찾은 후보의 순서 조정
- 화면 본문 우측 「같은 조건으로 비교」:
  - 관리형: Cohere Rerank 4 Pro/Fast
  - 자체 배포: Qwen3-Reranker, BGE 계열
  - 후보 수와 문서 길이를 고정
  - 답변 품질, 질문당 비용과 p95 지연 측정
- 화면 하단 강조: Anthropic 실험 5.7% → 1.9%: 문맥 보강, BM25와 리랭킹 전체 조합의 효과
- 상세 보기 링크: `#5-하이브리드-검색과-리랭킹`
- 화면 출처: Anthropic 벤더 실험(2024), Cohere Rerank 4, Qwen 공식 자료
- 발표자 노트:
  - 상위 20개 검색 실패율은 기본 임베딩 5.7%, 문맥 보강과 BM25 적용 2.9%, 리랭킹 추가 1.9%입니다.
  - 67%는 기본 임베딩 대비 전체 조합의 상대 감소율입니다. 리랭커만의 효과로 설명하지 않습니다.
  - RRF의 k=60은 설정 예시이며 필수값이 아닙니다. Weaviate는 v1.24부터 상대 점수 융합이 기본값입니다.
  - 후보에 없는 문서를 리랭커가 복구할 수는 없습니다. listwise LLM 방식도 항상 가장 정확한 것은 아닙니다.
  - Cohere Rerank 4 공개일은 2025-12-11입니다. Embed와 Rerank는 각각 벡터 생성과 후보 정렬을 맡습니다.

| Contextual Retrieval | 청크 앞에 원문 맥락 설명 추가 |
| Late chunking | 전체 문맥 반영 후 청크 단위 풀링 |
| Docling HybridChunker | 문서의 제목, 표와 절 구조 활용 |
| ColPali / ColQwen | 문서 페이지 이미지를 다중 벡터로 검색 |
| RAPTOR | 요약을 계층화해 긴 문서 탐색 |

- 화면 본문 우측 「쿼리 변환」:

| 기법 | 하는 일 |
|---|---|
| HyDE | 가상의 답을 만들어 검색 표현으로 사용 |
| Multi-query | 질문을 여러 표현으로 바꿔 검색 |
| Step-back | 더 추상적인 질문을 함께 검색 |
| Decomposition | 하위 질문으로 나눠 검색 |

- 화면 하단: 한 번에 여러 기법을 겹치기 전에 추가 호출 비용과 근거 품질을 측정합니다.
- 상세 보기 링크: `#6-청킹-인덱싱-쿼리-변환`
- 화면 출처: Anthropic Contextual Retrieval, Jina late chunking, ColPali 논문
- 발표자 노트:
  - 청크 맥락 설명을 생성하는 방식과 토큰 벡터에 전체 문맥을 반영하는 late chunking은 서로 다른 방식입니다.

## 슬라이드 12. RAG 평가와 관측

- 리드문: 맞는 근거를 찾았는지와 그 근거로 답했는지를 나누어 보고, 실패 과정을 추적합니다.

  - RAGAS는 설치 버전의 API와 문서 고정
  - LangSmith, Langfuse, Phoenix 등으로 추적
  - 실패 질문을 다음 회귀 평가에 추가
- 상세 보기 링크: `#12-rag-평가와-관측`
- 화면 출처: RAGAS 공식 문서, Anthropic 평가와 실행 추적 사례
- 발표자 노트:
  - 답변 관련성이 높다고 사실이 맞는 것은 아닙니다. 정답 여부와 근거성을 따로 평가합니다.
  - RAGAS로 만든 질문도 사람이 검토해야 하며, 실제 운영 실패 질문으로 보완합니다.
  - 평가 환경의 RAGAS 버전과 모델 설정을 고정하고, 업그레이드 시 같은 평가셋으로 결과를 비교합니다.
  - OpenTelemetry 사용만으로 모든 관측 도구의 기능과 이전 작업이 동일해지는 것은 아닙니다.
  - https://docs.ragas.io/en/latest/concepts/test_data_generation/rag/
  - https://www.anthropic.com/engineering/multi-agent-research-system

## 슬라이드 13. 멀티 소스 라우팅 아키텍처

- 제목: 질문과 결과 유형에 맞는 검색 경로
- 리드문: 문서 후보는 융합하고, SQL 집계값은 단위와 기준 시점을 확인해 답변에 결합합니다.
- 시각 배치: 상단 y 1.90 ~ 3.40″에 결과 유형이 구분되는 2경로 도식을 둡니다.  
  하단 y 3.65″에 구역 제목, y 4.20 ~ 7.23″에 6행 표를 배치합니다. 표는 14 ~ 16pt, 행 높이 0.43″ 이상을 확보합니다.
- 화면 본문 상단 도식:
  - 질문 → 라우터 → 문서 검색(BM25, 벡터, 그래프) → 후보 융합 / 리랭킹 → 근거 기반 답변
  - 라우터 → SQL 질의 → 단위와 기준 시점 검증 → 근거 기반 답변
- 화면 본문 하단:

| 질문 유형 | 질문 예시 | 비교할 경로 |
|---|---|---|
| 식별자 | 오류 코드 E-4021 원인 | 키워드와 벡터 |
| 의미 유사 | 카드 분실 시 처리 | 벡터와 키워드 결합 |
| 집계 | 지난달 지점별 매출 | SQL과 시맨틱 레이어 |
| 관계 | 임원이 관여한 계열사 | 그래프 탐색 또는 Cypher |
| 전체 조망 | 문서 묶음의 주요 쟁점 | 그래프 요약 또는 긴 문맥 |
| 시간 변화 | 지난달과 달라진 정책 | 시점 정보와 원문 검색 |

- 상세 보기 링크: `#13-멀티-소스-라우팅-아키텍처`
- 화면 출처: Neo4j, Microsoft 검색 공식 자료. 경로 표는 교육팀 설계 제안
- 발표자 노트:
  - 숫자 집계값 자체를 RRF의 검색 순위처럼 합치지 않습니다. 출처, 단위, 기준 시점과 계산 조건을 확인합니다.
  - SQL 결과에서 문서를 추가 검색하는 복합 흐름도 가능하지만, 결과의 의미를 보존하는 결합이 필요합니다.
  - 긴 문맥 경로는 표에서 선택지로 보여 줍니다. 모든 경로를 억지로 리랭커 하나에 연결하지 않습니다.
  - https://neo4j.com/docs/neo4j-graphrag-python/current/user_guide_rag.html
  - https://learn.microsoft.com/en-us/Azure/search/agentic-retrieval-overview

## 슬라이드 14. 교육팀 적용 제안

- 제목: 비교 실험으로 확장하는 6단계 실습
- 리드문: 검색 기준선을 먼저 만들고, 각 기법의 품질 개선과 추가 비용을 확인하며 확장합니다.
- 시각 배치: 전폭 14.9″의 6행 표를 y 2.25″부터 배치합니다. 행 높이는 0.62″ 이상으로 둡니다.
  본문은 16pt 이상이며, 하단 y 6.85″에 교육 원칙 한 줄을 표시합니다.
- 화면 본문:

| 단계 | 실습 내용 | 관련 실습 |
|---|---|---|
| 1. 검색 기준선 | BM25와 벡터를 각각 측정한 뒤 융합과 리랭킹 추가 | RAG 인덱싱과 검색 |
| 2. 색인 품질 | 문서 구조와 청크 문맥 보존 효과 비교 | 청킹 비교 |
| 3. 구조화 질의 | 업무 지표, 용어집과 SQL 예시를 함께 정의 | SQL retriever |
| 4. 그래프 | Neo4j 관계 확장과 벡터 기준선의 근거와 비용 비교 | 그래프 스키마 |
| 5. 라우팅 | 질문 6유형과 문서 / SQL 결과 처리 경로 구현 | 지식 경로 설계 |
| 6. 평가 | 실패 질문을 회귀 평가로 전환하고 실행 추적 | RAGAS와 관측 |

- 화면 하단: 벤더 발표와 연구 조건을 밝히고, 자사 질문에서 직접 비교합니다.
- 상세 보기 링크: `#14-교육팀-적용-제안`
- 화면 출처: hybrid-ai 교육팀 RAG 동향 보고서 14절
- 발표자 노트:
  - 관련 저장소: hands-on/solutions/rag, hands-on/solutions/sql-retriever.
  - 그래프 실습은 관계 확장과 원문 근거를 먼저 확인하고, 연구 기법의 구축 비용을 별도 비교합니다.
  - 단계별 정답 근거와 실패 질문을 유지하면 다음 기법의 이득과 퇴행을 같은 조건에서 확인할 수 있습니다.
  - 원문: 링크 기준 URL의 14절.
