## 슬라이드 1. 워크플로우 도식
- 제목: GraphRAG Agentic 검색: 2단계가 검색 모드를 고르고, 3단계가 채점을 보고 조정함
- 리드문: 벡터 검색 워크플로우와 같은 뼈대에서 「문서 검색」을 「검색」 서브 워크플로우로 바꾸고, 리랭킹 단계를 더함
- 노드 요청: 동기 요청 | 질문 + 역할
- 노드 1: 1 | 요청 접수, 준비 확인
- 노드 2: 2 | 질문 분석, 검색 모드 결정
- 노드 3: 3 | 다음 행동 선택, 모드 조정
- 노드 4: 4 | 검색(O, L, G)
- 노드 5: 5 | 결과 채점(규칙)
- 노드 6: 6 | 질문 변환
- 노드 7: 7 | 리랭킹
- 노드 8: 8 | 수집 종료 판정
- 노드 9: 9 | 답변 생성(옵션)
- 노드 10: 10 | 근거 검증(규칙)
- 종료 오류: 11 | 오류
- 종료 불필요: 11 | 검색 불필요
- 종료 확인: 11 | 확인 필요(clarify)
- 종료 근거: 11 | 검색 결과, 근거 없음
- 종료 완료: 11 | 답변 완료, 확인 필요(2회 소진)
- 종료 실패: 11 | 생성 실패(근거 목록만)
- 화살표 글: 설정, 권한 오류 | 인사, 잡담 | 단순, 복합 | 질문 변환 | 변환 질의 | keep 1회 | 수집 종료 | 답변 생성 켬

  - 4단계 검색은 서브 워크플로우 셋(검색엔진 검색 O, Local 검색 L, Global 검색 G)으로 이루어져 담당자 유형이 하나가 아니라서 따로 표시했습니다(9장).

## 슬라이드 3. 2단계 검색 모드 결정
- 제목: 2단계 검색 모드 결정: 규칙 신호를 먼저 보고, 남는 판단만 LLM이 함
- 리드문: 모드는 local과 global 둘뿐이며, 확신이 낮으면 local로 시작해 뒤에서 조정할 여지를 남김
- 표 열 너비: [2.2, 6.4, 6.3]

| 모드 | 고르는 경우 | 하는 일 |
|---|---|---|
| local | 카드, 조항, 회원, 금액 같은 사실. 확신이 낮을 때 기본값 | Local 검색 L1 ~ L4 |
| global | 여러 문서의 경향, 공통점, 주제 나누기. 경향과 근거 사실을 함께 물을 때도 | Global 검색 G1 ~ G3 |

- 규칙 카드 제목: 규칙 신호와 식별자
- 규칙 카드:
  - 회원번호, 카드명, 조항 번호 → local. 「주제별」, 「공통점」, 「경향」, 「고객군별」 → global
  - 회원번호 → 가명 id, 카드명 → card_id로 바꿔 두 저장소의 메타데이터 필터로만 씀(상담 본문에 회원번호가 없음)
  - 보고서가 없는 세대면 global을 고르지 않음
  - 이 실습의 local과 global은 자체 검색 모드임. Global은 Microsoft Global Search(map-reduce)와 다르고, DRIFT와 닮았지만 같지 않음
- 화면 출처: teacher/plan/graphrag-agentic-search.md 0장, 2-1절. Microsoft GraphRAG 검색 방식 개요와 DRIFT 문서
- 상세 보기 링크: #2-1-단계-2의-처음-결정-adaptive
- 발표자 노트:
  - 이 단계가 Adaptive RAG에 해당합니다. 질문을 보고 처음 검색 전략을 고릅니다.
  - 기본값을 local로 둔 까닭은 사실 질문이 대부분이고, global 검색을 요청당 1번만 허용하기 때문입니다.

## 슬라이드 4. 5단계 채점과 진단 신호
- 제목: 5단계 채점과 진단 신호: 점수와 함께 「왜 부족한지」를 알려 줌
- 리드문: 관련도는 질문과 보고서 요약 임베딩의 코사인 유사도이며, 기준값은 모두 평가셋으로 조정할 가정값임
- 표 열 너비: [3.2, 7.4, 4.3]

| 신호 | 판정 규칙(가정값) | 뜻 |
|---|---|---|
| PASS(local) | 핵심어 포함률 0.6 이상, 원문 2개 이상, 식별자 메타데이터 일치 | 사실 근거 충분 |
| PASS(global) | 관련도 0.35 이상 보고서 2개 이상, 주제마다 원문 1개 이상 | 경향과 근거 충분 |
| NO_COOCCUR | 핵심 명사 두 개가 한 문장에 함께 나온 근거 0건(global은 주제마다) | 함께 언급된 근거 없음 |
| NO_SEED | 검색엔진 검색 결과 0건 | 낱말이 색인과 안 맞음 |
| LOW_COVERAGE | 포함률 0.6 미만, 또는 청크 엔티티 3개 미만 | 질문의 일부만 근거 있음 |
| SCATTERED | 원문 4개가 문서 3종 이상, 포함률 0.6 미만(필터 질의 제외) | 질문이 넓음 |
| NO_REPORTS | 보고서 0건 | 보고서 없음 |
| OFF_TOPIC_REPORTS | 보고서는 있는데 관련도 최댓값 0.25 미만 | 보고서 주제가 어긋남 |
| ID_MISMATCH | 필터 밖 근거가 섞임 | 다른 회원이나 카드 |
| NO_NEW | 새 근거 0건 | 더 찾아도 소용없음 |

- 화면 출처: teacher/plan/graphrag-agentic-search.md 2-2절, 지식니 실측(청크 260개, 보고서 78개)
- 상세 보기 링크: #2-2-단계-5의-채점과-진단-신호-규칙
- 발표자 노트:
  - 핵심어 포함률의 분모는 명사, 숫자, 코드 토큰만 셉니다. 「쓰」, 「하」 같은 동사 어간은 어느 청크에나 있어 뺍니다.
  - NO_COOCCUR 실측: Q18(연회비와 포인트) 0문장, Q20(버전과 연회비) 0문장, Q01(연회비와 면제) 5문장입니다.
  - NO_COOCCUR는 「답이 없음」이 아니라 「함께 언급된 근거를 찾지 못함」입니다. 다른 문장이나 문서의 관계를 이어야 답할 수 있는 질문도 있어서, 처음에는 질문을 나눠 한 번 더 찾습니다(5장).
  - 관련도 점수는 LLM이 내지 않습니다. G1에서 LLM이 보고서를 고른 뒤, 고른 보고서마다 임베딩 유사도를 따로 계산합니다.
  - 관련도 최댓값이 0.25 이상인데 0.35 이상 보고서가 2개 미만이면 LOW_COVERAGE로 봅니다.
  - 분해 뒤에는 원 질문 기준으로 다시 확인합니다. 원 질문의 핵심 명사 두 개가 한 문장에 있거나, 그래프 관계 하나로 이어진 두 엔티티의 원문에 나뉘어 있어야 합니다. 지식니 실측에서 Q18을 연회비와 포인트로 쪼개면 「포인트 사용」만 23문장이 나와 함정 질문이 통과해 버렸기 때문입니다.
  - 핵심 명사가 5개 미만인 짧은 질문은 공존 1건 이상과 원문 2개 이상이면 통과로 봅니다.
  - SCATTERED에서 필터 질의를 뺀 까닭: 한 회원의 상담 4건은 원래 여러 문서에 흩어져 보여 오탐이 납니다.
  - OFF_TOPIC_REPORTS를 둔 까닭: 보고서 78개 중 65개가 카드 혜택 계열이라 상담 질문에 엉뚱한 보고서가 걸리기 쉽습니다.

## 슬라이드 5. 3단계 모드 조정
- 제목: 3단계 모드 조정: 신호에 따라 다음 행동을 고르고, 금지 규칙으로 맴돌지 않게 함
- 리드문: 계획대로 가는 일은 규칙으로 정하고, 신호가 겹치거나 표에 없을 때만 LLM이 정해진 행동 중 하나를 고름
- 표 열 너비: [3.0, 1.6, 6.9]

| 신호 | 지금 모드 | 3단계 행동 |
|---|---|---|
| PASS | 아무 모드 | 수집 종료 |
| NO_COOCCUR | local, global | local: 분해 → 하위 질문별 local, 원 질문 기준 재확인, 남으면 종료. global: 그 주제만 미확인 |
| NO_SEED | local | 질문 다시 쓰기 → local |
| LOW_COVERAGE | local | 복합 질문: 분해 → 하위 질문별 local. 단순 질문: 다시 쓰기 → local |
| SCATTERED | local | global로 전환 |
| NO_REPORTS, OFF_TOPIC_REPORTS | global | 처음부터 global: local로 전환. local에서 전환해 옴: 수집 종료 |
| ID_MISMATCH | local, global | local: 필터 강화 재검색 1회. 그 뒤나 global: 필터 밖 근거를 지우고 수집 종료 |
| NO_NEW | 아무 모드 | 수집 종료 |

- 금지 카드 제목: 금지 규칙(우선)
- 금지 카드:
  - 같은 모드, 질의, 필터 조합은 두 번 검색하지 않음
  - global 검색 1번, 모드 전환 1번(반대 방향 금지)
  - 질문 분해 1번, 필터 강화 재검색 1번, keep 1번
  - 행동이 금지에 걸리면 수집 종료
  - G3의 Local 검색은 전환으로 세지 않음
- 화면 출처: teacher/plan/graphrag-agentic-search.md 2-3절, 플로니 검토(진동 방지)
- 상세 보기 링크: #2-3-단계-3의-조정-agentic
- 발표자 노트:
  - 이 단계가 Agentic RAG에 해당합니다. 결과를 보고 다음 검색 전략을 스스로 바꿉니다.
  - 구현할 때 3단계는 행동을 정해 상태에 적는 노드와, 상태만 읽어 갈 곳을 고르는 분기 함수로 나눕니다.
  - 금지 규칙이 행동표보다 앞섭니다. 예를 들어 local에서 global로 전환한 뒤 보고서가 없으면, 다시 local로 돌아가지 않고 앞서 모은 local 근거로 수집을 끝냅니다.
  - LLM이 행동을 고를 때는 금지 규칙을 통과한 행동 목록만 보여 줍니다.
  - 다시 쓴 질의와 하위 질문은 원 질문의 식별자 필터를 그대로 물려받습니다. 필터가 풀리면 Q21, Q22가 다른 회원의 근거로 답하게 됩니다(지식니 실측: 필터 없이 6문장, 4문장).
  - 「처음부터 global」인지 「local에서 전환해 온 global」인지는 2단계가 처음 고른 모드(initial_mode)로 가립니다.

## 슬라이드 6. 4단계 검색과 검색엔진 검색(O)
- 제목: 4단계 검색: 세 서브 워크플로우가 쌓이고, 바닥은 검색엔진 검색(O)
- 리드문: Local 검색(L)이 검색엔진 검색(O)을 품고 Global 검색(G)이 Local 검색을 품으며, 셋 다 4단계 노드 안의 함수로 돌림
- 쌓임 1: Global 검색(G) | G1 커뮤니티 검색 → G2 Follow-up 질문 → G3 Follow-up Local 검색
- 쌓임 2: Local 검색(L) | L1 검색엔진 검색 → L2 엔티티 축소 → L3 이웃 탐색 → L4 커뮤니티 탐색
- 쌓임 3: 검색엔진 검색(O) | O1 벡터 검색 + O2 BM25 검색 → O3 RRF → O4 리랭킹
- 흐름 제목: 검색엔진 검색(O)
- 흐름: O1 벡터 검색 → 최대 25 | O2 BM25 검색 → 최대 25 | O3 RRF → 중복 제거 25 | O4 리랭킹 → 최대 6
- 흐름 설명: 같은 질의로 O1과 O2를 병렬 실행. 식별자 필터와 세대를 두 쪽에 똑같이 걸고, 필터로 후보가 6개 이하면 O4를 건너뜀
- 결정 카드 제목: 최적안 결정
- 결정 카드:
  - O3 RRF는 코드에서. O1, O2 중 한쪽이 죽어도 남은 순위로 부분결과를 냄. OpenSearch 파이프라인 RRF는 선택지로 남김
  - O4 리랭커는 Cohere rerank-v4.0-fast. RAG 실습 코드와 같고 7단계에서도 같은 리랭커를 씀
- 화면 출처: teacher/plan/graphrag-agentic-search.md 4, 4-1절
- 상세 보기 링크: #4-1-검색엔진-검색o-벡터-검색--bm25-검색--rrf--리랭킹
- 발표자 노트:
  - LangGraph 서브그래프로 쪼개지 않고 4단계 노드 안의 함수로 두는 까닭은, 3단계의 금지 규칙과 진입 횟수 판정이 그래프 경계를 넘지 않게 하기 위해서입니다. 병렬은 노드 안에서 asyncio.gather로 합니다.
  - OpenSearch 2.19.1의 score-ranker-processor(rrf)는 파이프라인 생성이 정상임을 확인했습니다. 호출을 한 번으로 줄이고 싶을 때 바꿀 수 있습니다.
  - 로컬 크로스 인코더는 현재 CPU 실습 환경에서 Follow-up 5갈래 × 25건을 처리할 때 병목이 예상되어 뺐습니다(측정하지 않은 판단입니다). OpenSearch rerank 프로세서는 파이프라인 안에만 있어 7단계에 쓸 수 없습니다.

## 슬라이드 7. Local 검색(L)
- 제목: Local 검색(L): 청크로 시작점을 찾고, 엔티티를 줄여 이웃과 보고서로 넓힘
- 리드문: 검색엔진이 찾은 청크의 엔티티를 노드 설명 벡터로 줄이므로, 엔티티는 늘 청크 근거와 이어짐
- 흐름 제목: Local 검색(L)
- 흐름: L1 검색엔진 검색 → 6 | L2 엔티티 축소 → 16 | L3 이웃 탐색 → 각 4 | L4 커뮤니티 탐색 → 3
- 흐름 설명: L1은 서브 워크플로우 O를 부름. L2 ~ L4는 Cypher 1번으로 처리하고 상한은 파라미터로 넘김
- 카드 1 제목: L2 엔티티 축소(노드 설명 벡터)
- 카드 1:
  - 청크 6개의 엔티티(중앙값 52개)를 질문 벡터와 노드 설명 임베딩의 코사인 유사도로 줄 세움
  - 청크마다 최소 1개 보장, 전체 16개. 상담 질문은 첫 상담과 가장 최근 상담을 축소 전에 먼저 고정
  - 벡터 인덱스 교집합은 안 씀: 엔티티 벡터만으로 Q01, Q09 시작점을 놓친 검증 결과가 있음
- 카드 2 제목: 장애 때
- 카드 2:
  - 검색엔진 장애: 엔티티 벡터 상위 3개를 비상 시작점으로 쓰고 「그래프만」 경고
  - Neo4j 장애: 검색엔진 원문만으로 답하고 「그래프 근거 없음」 경고
  - 리랭커 장애: O3 RRF 순위 그대로 6개
- 화면 출처: teacher/plan/graphrag-agentic-search.md 4-2, 4-5절. 지식니 실측(청크당 엔티티 중앙값 9개, 규정 청크 30개)
- 상세 보기 링크: #4-2-local-검색l-검색엔진-검색--엔티티-축소--이웃-탐색--커뮤니티-탐색
- 발표자 노트:
  - 상한을 8개가 아니라 16개로 둔 까닭: 규정 청크는 엔티티가 30개라, 8개로 자르면 답이 든 조항 노드가 떨어져 나갑니다. 이웃을 6개에서 4개로 줄여 총량을 맞췄습니다.
  - L3 이웃 탐색은 그래프에서 이웃을 찾는 일(규칙)과 남길 순서를 정하는 일(임베딩 유사도)이 섞여 있습니다. 도식에서는 주된 쪽인 규칙기반으로 칠했습니다.
  - 실측 수치는 이전 세대 색인 결과 기준입니다. 현 세대에서는 조금 다를 수 있습니다.

## 슬라이드 8. Global 검색(G)
- 제목: Global 검색(G): 보고서로 주제를 잡고, 주제마다 Follow-up Local 검색을 함
- 리드문: 이 실습의 자체 구성으로, LLM이 보고서 제목을 보고 고른 뒤 주제마다 Follow-up Local 검색으로 사실 근거를 붙임
- 흐름 제목: Global 검색(G)
- 흐름: G1 커뮤니티 검색 → 보고서 ≤ 12 | G2 Follow-up 질문 → 1 ~ 5개 | G3 Follow-up Local 검색(병렬)
- 흐름 설명: G3은 질문마다 서브 워크플로우 L을 부름. 근거마다 주제 id(topic_id)를 붙이고, 주제마다 보고서 id 목록(report_ids)을 둠
- 카드 1 제목: G1 커뮤니티 검색(보고서 고르기)
- 카드 1:
  - 보고서 제목 78개(약 1,150 토큰)를 LLM에 보이고 관련 보고서를 고르게 함. 상한 12
  - 보고서 본문 몫은 12,000 토큰. 고른 뒤 실제로 세고, 넘으면 관련도 낮은 보고서부터 뺌(측정한 상담 계열 12개는 약 11,700 토큰)
  - LLM 실패면 보고서 벡터 상위 5개
- 카드 2 제목: G2 Follow-up 질문
- 카드 2:
  - 고른 보고서를 주제로 묶어 주제 id를 붙이고, 주제마다 「사실로 확인할 것」을 하나씩(1 ~ 5개)
  - 항상 함: global은 요청당 1번이라 다시 못 함. 원문을 못 찾은 주제는 답에서 미확인으로 표시
  - LLM 실패면 상위 보고서의 제목 + 요약 첫 문장을 질문으로
- 화면 출처: teacher/plan/graphrag-agentic-search.md 4-3절. 지식니 실측(보고서 78개, 상담 계열 12개, 전문 약 76,000 토큰)
- 상세 보기 링크: #4-3-global-검색g-커뮤니티-검색--follow-up-질문--follow-up-local-검색
- 발표자 노트:
  - 벡터 상위 5개로 고르면 상담 계열 보고서 12개 중 최대 5개만 담깁니다(보고서 포함 상한 5/12. 계산값이며 실제 검색 재현율을 잰 것은 아닙니다). 「예산 안이면 전부」는 전문이 76,000 토큰이라 발동하지 않습니다.
  - Microsoft GraphRAG의 Global Search는 보고서를 map-reduce로 처리합니다. 이 실습의 Global은 보고서 선택과 Follow-up Local 검색을 결합한 자체 구성이며, DRIFT와 닮았지만 후속 질문마다 중간 답을 만들지 않고 깊이도 1입니다.
  - 플로니는 단순한 벡터 상위 5개를 권했고, 지식니는 제목 전수 선별을 권했습니다. 실측 재현율 근거로 지식니 안을 택했고, LLM 실패 시 플로니 안으로 내려가므로 둘 다 구현합니다.

## 슬라이드 9. 4단계의 담당자 유형
- 제목: 4단계 검색은 예측형AI 하나가 아니라, 서브 단계마다 담당자 유형이 다름
- 리드문: 가이드 기준(「그 일을 누가 판단하나」)으로 보면 임베딩과 리랭커는 예측형AI, 공식은 규칙, 보고서 고르기와 질문 만들기는 생성형AI임
- 표 열 너비: [3.0, 5.2, 2.9, 3.8]

| 서브 단계 | 판단하는 것 | 담당자 유형 | 까닭 |
|---|---|---|---|
| O1 벡터 검색 | 질의와 청크가 의미상 가까운가 | 예측형AI | 학습된 임베딩 모델의 유사도 |
| O2 BM25 검색 | 질의 낱말이 얼마나 나오나 | 규칙기반 | 학습 없는 통계 공식 |
| O3 RRF | 두 순위를 어떻게 합치나 | 규칙기반 | 1/(60 + 순위) 공식 |
| O4 리랭킹 | 질의와 청크의 관련도 점수 | 예측형AI | 관련도를 예측하는 크로스 인코더 |
| L2 엔티티 축소 | 어떤 엔티티가 질문과 가까운가 | 예측형AI | 노드 설명 임베딩 유사도 |
| L3 이웃 탐색 | 어떤 이웃을 남기나 | 규칙 + 예측형AI | Cypher 탐색, 유사도 순서 |
| L4 커뮤니티 탐색 | 어떤 보고서를 붙이나 | 규칙기반 | 관계와 걸린 횟수 |
| G1 커뮤니티 검색 | 어떤 보고서가 관련 있나 | 생성형AI | LLM이 제목을 읽고 고름 |
| G2 Follow-up 질문 | 무엇을 사실로 확인할까 | 생성형AI | LLM이 질문을 만듦 |

- 화면 출처: teacher/plan/graphrag-agentic-search.md 4-0절, references/design-workflow-connector.md 1-2절(담당자 유형)
- 상세 보기 링크: #4-0-단계-4의-담당자-유형
- 발표자 노트:
  - 벡터 검색 워크플로우에서 「문서 검색」을 예측형AI로 본 것은 벡터 검색과 리랭킹이 판단의 중심이기 때문입니다. 그 단계만 보면 맞는 분류입니다.
  - 이 설계의 4단계는 Global 모드에서 LLM이 보고서를 고르고 질문을 만듭니다. 그래서 예측형AI 하나로 적으면 틀리고, 메인 도식에서는 「서브 워크플로우」로 따로 칠했습니다.
  - L1과 G3은 다른 서브 워크플로우를 부르는 단계라 표에서 뺐습니다(L1은 O, G3은 L).
  - G1은 LLM이 실패하면 보고서 벡터 유사도(예측형AI)로 내려갑니다.

## 슬라이드 11. 7단계 리랭킹과 결정 사항
- 제목: 7단계 리랭킹: 회차마다 섞인 근거를 원 질문 기준으로 다시 줄 세움
- 리드문: O4는 회차 질의 기준 25에서 6, 7단계는 원 질문 기준 누적에서 8이라 역할이 겹치지 않음
- 흐름 제목: 7단계 리랭킹
- 흐름: 모은 원문 전체 | 원 질문 기준 리랭킹 → 8 | 이어진 엔티티만 남김 | 보고서는 걸린 횟수, 관련도 순
- 흐름 설명: global 모드는 주제(topic_id)마다 원문을 최소 1개 보존하고 8단계에서 다시 확인. 회차가 1회이고 원문이 8개 이하면 건너뜀
- 결정 제목: 사용자 결정과 검토 반영
- 결정:
  - 단계 ID: 메인 1 ~ 11, 서브 O1 ~ O4, L1 ~ L4, G1 ~ G3. 반복 구간은 반복 1, 반복 2. 분기 번호 없음
  - 4단계 이름은 「검색」, 모드는 local과 global만(둘 다 하이브리드), 수집 종료 판정 전 리랭킹, 시간 예산 제외
  - 지식니: 상한 16, 식별자는 메타데이터, SCATTERED 필터 제외, OFF_TOPIC_REPORTS 신호
  - 플로니: 비상 시작점, Cypher 1번, 노드 안 병렬, topic_ids 목록, 모드 중첩은 세지 않음
  - 외부 리뷰: NO_COOCCUR는 분해로 1번 재시도, 금지 규칙 우선, 주제별 통과 기준, 관련도 정의, 자체 구성 명시
